System Architecture — Updated

Thin API routes. Business logic in dedicated service modules. Scheduling engine designed for background job extraction.

API Routes (Thin)

/api/* — Request/Response Only

  • Parse request, validate auth session
  • Call the appropriate service module
  • Return result or error — nothing else
  • No business logic lives here
Domain Service Modules

lib/services/

  • scheduling/ — schedule generation engine (3 passes)
  • availability/ — submission logic, validation
  • guards/ — guard profiles, court eligibility
  • periods/ — period lifecycle, status transitions
  • admin/ — courts, config, capacity rules
  • fairness/ — scoring, history, warnings
  • validations/ — conflict rules, constraint checks
Scheduling Engine (Isolated Module)

lib/services/scheduling/

  • Pass 1: Slot filling — hard constraints only
  • Pass 2: Weekly minimum prioritization (best-effort, within submitted availability)
  • Pass 3: Fairness rebalancing, opening duty rotation
  • Pure function: takes inputs, returns draft + warnings
  • No HTTP, no side effects — easy to extract to background job
Data Layer

PostgreSQL + Prisma

  • Repository pattern: lib/db/ wraps Prisma queries
  • Services call repositories — never Prisma directly
  • Clean seam: easy to swap query implementations
  • NextAuth adapter in the same DB

Layered Call Chain

HTTP Request → API Route (thin) → Service Module → Repository → Prisma → PostgreSQL

Background Job Readiness

The scheduling engine is a pure function with no HTTP dependencies. In V1, the API route calls it directly and awaits the result. When/if generation becomes slow enough to warrant async processing, the same function can be invoked by a job runner (BullMQ, pg-boss, Inngest) with zero changes to the engine itself — only the API route changes (returns a job ID instead of waiting).

V1 (synchronous) POST /api/schedule/generate
→ calls engine() → saves draft → returns result
V2 (background job) POST /api/schedule/generate
→ enqueues job → returns jobId
Job runner calls same engine() → saves draft
