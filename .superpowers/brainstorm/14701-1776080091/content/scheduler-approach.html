Scheduling Algorithm: Which Approach?

The algorithm must fill 14 days × multiple courts × 3 shifts while respecting hard constraints and optimizing for fairness. Three viable strategies:

A

Weighted Scoring + Greedy Assignment (Recommended)

Each candidate guard gets a score for each slot based on fairness history, workload balance, and constraint satisfaction. The highest-scoring eligible guard gets assigned first.

Score formula per candidate:
+ fewer total shifts assigned this period → higher score
+ fewer night/weekend/opening duties historically → higher score
+ weekly minimum not yet met → priority boost
− conflict risk (same day/next morning) → heavy penalty
− over court capacity → excluded entirely

Pros

  • Fast — runs in milliseconds even for 150 guards
  • Predictable, explainable results the manager can understand
  • Easy to tune: adjust weights to change fairness priorities
  • Naturally produces warnings when constraints can't be met
  • Works well for 50–150 guards at medium scale

Cons

  • Greedy — may not find globally optimal solution
  • Assignment order matters; early slots affect later ones
  • May need multi-pass (2nd pass to fix unmet minimums)
B

Integer Linear Programming (ILP / Constraint Solver)

Model the entire scheduling problem as a mathematical optimization. A solver (e.g., GLPK, OR-Tools) finds the globally optimal assignment given all constraints.

Pros

  • Mathematically optimal — best possible schedule every time
  • All constraints are declarative and verifiable
  • Handles complex interdependencies correctly

Cons

  • Significant implementation complexity — requires solver library or service
  • Slow for large problem spaces (150 guards × 14 days × 3 shifts × 15 courts)
  • Hard to explain to managers why it made specific choices
  • Overkill for medium scale — greedy gets ~90% of the quality at 5% of the cost
  • Difficult to add custom weights/fairness tuning
C

Multi-Pass Weighted Greedy (Extended A)

Same as Option A, but runs 3 explicit passes: (1) hard constraints only, (2) weekly minimums, (3) fairness optimization. Each pass fixes what the previous missed.

Pros

  • Better at satisfying weekly minimums than single-pass greedy
  • Still fast and explainable
  • Natural place to generate per-pass warnings
  • Graceful degradation — each pass reports what it couldn't fix

Cons

  • Slightly more complex to implement than single-pass
  • Still not globally optimal, but much closer than single-pass
  • Need to carefully define pass boundaries

Why I Recommend Option C (Multi-Pass Weighted Greedy)

For a scheduling system where weekly minimums (2 morning + 1 evening per guard per week) and fairness across multiple dimensions are both important, a single greedy pass often trades one for the other. Multi-pass solves this cleanly:

  • Pass 1: Fill all slots respecting hard constraints (capacity, conflicts, court eligibility)
  • Pass 2: Check weekly minimums — add missing assignments where availability allows
  • Pass 3: Fairness rebalancing — swap assignments where history is uneven

Each pass surfaces its own warnings. The manager sees exactly which minimums couldn't be met and why. It's ~85% as good as ILP but 10× simpler and fully explainable.
