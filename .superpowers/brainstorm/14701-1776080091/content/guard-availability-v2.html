What changed from previous version
Removed: court selection entirely

Guard sees their primary court in the header (context only, not selectable). Each day now has just 3 toggles: בוקר / ערב / לילה. Half the taps, half the cognitive load.

Data model stays multi-court capable

User gains a primaryCourtId field. AvailabilityEntry is still per-court in the DB — the service layer fills in primaryCourtId automatically. When a guard is eligible for multiple courts, a future UI extension adds court selection per toggle without restructuring the schema.

Unchanged UX patterns
  • Accordion-style expand one day at a time
  • Color dot summary on collapsed rows
  • Sticky progress bar + submit button
  • Auto-save as draft, explicit submit action
  • Fully Hebrew RTL throughout
